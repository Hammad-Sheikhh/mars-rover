# Changelog

Notable changes to this project. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Vision cost control (milestone 9):** one description now serves many Jev decisions. The station asks the vision AI again only when there is no description, the rover has moved 14 steps (a turn counts as 6), the description is 12 s old, something within 60 cm is 20 cm closer, or Jev was unsure on an older view. A run makes at most `VISION_MAX_CALLS` live descriptions (default 6, pre-flight and failed/rate-limited attempts included), and the safety gate refuses **forward** on a description older than 20 s or 24 steps (turns and reverse stay allowed at the gate). If the budget is spent and the view is stale, or no description succeeds for 60 s, the station stops the rover and ends the run cleanly instead of waiting forever. Mission control now shows how many vision calls were used and how many are left, plus when the budget is spent or the run gave up.
- **The example settings now match the floor-tested hardware:** Gemini 3.5 Flash, a 30 s vision timeout, a 20 s scene window, full power (255) and 500 ms chained pulses. The old `170`/`300` example only beeped the 2–3 kg rover; the old Lite model took 19–50 s or timed out.
- **Pre-flight survives the rover's `/sensors/data` hiccup.** The endpoint drops a single answer for a fraction of a second every ~20 s; one bad read used to abort the whole run before it started. Pre-flight now retries three times, 0.5 s apart.
- **The Earth Station no longer spends Jev calls it cannot use.** If the camera description or the rover readings are stale, the safety gate would veto the answer anyway, so the station sends one stop, waits, and asks Jev again only when fresh data arrives. A vision rate limit now backs off 15 s → 30 s → 60 s → 120 s instead of retrying every 5 s (which kept the free-tier quota saturated), and a spent `JEV_MAX_CALLS` budget ends the run immediately even if the scene is stale. The brief Jev reads now also states the camera's structured **open side** and **obstacle ahead** flag, so it no longer has to infer the safe direction from prose alone.
- **Gemini free-tier reality check:** the quota is per model **per day** (Gemini 2.5 Flash: 20 requests/day at the time of writing, retry shown as ~15 h). A 10-call drive can exhaust it, so a long vision drive needs billing (~$0.05–0.12 per driving hour) or a higher-quota model; the station now handles the 429 cleanly either way.
- **Rover firmware 2.5.4/2.5.5 — the hotspot was blocking the board's MAC, not the firmware.** The rover failed to join the phone hotspot with `status=6` and a storm of `wifi:Set status to INIT` driver lines, while the same board joined a normal router and the camera's own access point instantly. The hotspot had the rover's factory STA MAC blocked: the same sketch joined it in under a second after changing only the MAC. Firmware 2.5.4 set a fixed locally-administered STA MAC (`02:4D:52:53:01:01`) before `begin()`, until the block was cleared on the phone. The block was cleared the same evening, so **2.5.5 removes the workaround and uses the chip's factory MAC again**. It also folds in the 2.5.2/2.5.3 join-order work (join the hotspot alone first, AP after; `mode -> disconnect -> begin`; sleep off only after the radio is up). Verified live: 2.5.4 joined with the alternate MAC, then 2.5.5 joined with the factory MAC after the block was removed; `/sensors/data` stayed at 229–287 ms over 12 calls with `i2c_ok=1` and `i2c_recov=0`, and all 12 `--check` items pass.
- **Rover firmware 2.5.1 — the `/sensors/data` hiccup fix pack** (the watch item from the first bench drive: the endpoint hiccuped every ~20–25 s even with uploads off). All slow/blocking work moved out of the HTTP handlers into `loop()` on timers: BMP280 + DHT11 readings are refreshed every 2 s and `/sensors/data` only formats a cached snapshot from a fixed-size buffer (no chained `String` allocations); the ultrasonic `pulseIn` block is capped at 12 ms (~2 m, was 30 ms); the Wi-Fi modem sleep is off (modem-sleep TX bursts saturated the web server); the 12 KB control page is served straight from flash instead of being copied to the heap on every load; the Supabase path is compiled out entirely (it needs a code change to come back, not a constant flip). New diagnostics: the Serial heartbeat (`H`/`M`/`D`/`J` letters + a full `BEAT` line with free heap every 10 s) names the loop stage where a freeze happens, and `/sensors/data` reports `accX/accY/accZ`, `i2c_ok` and `i2c_recov` (count of automatic I2C-bus re-inits). Also: pitch/roll now come from the accelerometer via `atan2` (the gyro-integrated angles stuck at fake values after handling), the tilt-obstacle vetoes therefore can't refuse moves because of a stale angle, and `last_event` expires back to `Nominal` after 8 s.
- **Earth Station keeps its HTTP pool small**: at most 4 connections (2 kept alive) to the boards (the rover's Arduino WebServer accepts only a few simultaneous clients), so a stuck rover link can no longer stack abandoned sockets during a drive.
- **Photo descriptions can use Gemini (free) instead of Claude**: new setting `VISION_PROVIDER` (`gemini` or `anthropic`). Gemini 3.5 Flash (`gemini-3.5-flash`) answers as a direct description with thinking switched off, in the same agreed four-field shape, so Jev needs no change. A free key from [aistudio.google.com](https://aistudio.google.com) works with one photo every 10–15 s, subject to the free-tier daily quota (see above); ~$0.05–0.12 per driving hour if billing is ever enabled. New setting `VISION_FOCUS` (comma-separated objects the vision AI must watch out for, e.g. cables, drops, paws) is added to the photo prompt for either provider.
- **Camera + vision bench** (`python -m earth_station.bench`, pre-rover check): four phases on the standalone camera — `smoke` (5 photos: size, capture and describe latencies, valid answers), `stamina` (the live cadence for N minutes, with how much of the time the scene stayed inside the freshness window and every 429/refusal/timeout), `scene` (ground-truth probes: box ahead/left/right, covered lens, cable — scored against what was really there) and `burst` (12 fast calls to find where rate limiting starts, then one calm call). One JSON event per step in `runs/vision-bench-*.jsonl`, ending in a PASS/FAIL verdict against the camera and vision thresholds. Works with the simulator too (`DESCRIBE_MODE=mock`: camera numbers only, report says so). `--probe N` runs a single ground-truth probe with no Enter-waiting, so the probing can be driven remotely (each placement confirmed in chat) while the bench still logs and scores identically.
- **Camera firmware 2.2.0** — Supabase uploads off by default (`SUPABASE_UPLOAD 0` in `cam1/cam1.ino`). First live bench run caught the upload's TLS handshake stalling `/capture` (capture p95 2 s on, under 0.5 s off); the periodic upload also burned ~8,600 storage objects a day for no benefit now that vision descriptions reach the Earth Station live. Flip the constant to 1 to re-enable the old behaviour.
- **Rover firmware 2.2.0** — Supabase uploads off by default (`SUPABASE_UPLOAD 0` in `rover1/rover1.ino`), the same fix as the camera. The first live-Jev pre-flight caught the every-5-second upload's blocking TLS handshake stalling `/sensors/data` (answers 0.9–1.5 s against the station's 0.8 s timeout). During a drive all readings and decisions are recorded in the Earth Station's `runs/*.jsonl` logs instead. Flip the constant to 1 to re-enable the old behaviour.
- **Mission control page** (milestone 6): each run opens `http://127.0.0.1:8000` in the browser. It explains every decision in plain words, in four left-to-right steps (what the rover sees → what Jev chose → what the safety gate did → what the rover did), with a distance gauge, a table of the last 20 decisions, what was sent to Jev and confidence bars. It shows the latest photo and description, sensor readings, the rover's mode, and each link's status. A big **STOP** button (or `Esc`) stops the rover and pauses Jev until **Resume**. Only this laptop can use it. New flag `--no-browser` and setting `MISSION_CONTROL_PORT` (default 8000). Photo-description errors now show as `vision:` instead of `camera:`.
- **Jev spending guard**: each run makes at most `JEV_MAX_CALLS` real Jev calls (default 20, new setting). At the limit the station stops the rover, ends the run and prints the calls and tokens used. `--sim` now always uses the pretend Jev unless you add the new `--live-jev` flag, so practice runs are free.
- **Photo descriptions with Claude vision** (milestone 5): with `DESCRIBE_MODE=live` and an Anthropic key in `VISION_API_KEY`, each camera photo is described by Claude in the agreed shape (`summary`, `obstacle_ahead`, `clear_side`, `hazards`). New settings `VISION_MODEL` (default `claude-opus-5-5`), `VISION_EFFORT` (default `low`) and `VISION_TIMEOUT_S` (default 10). `python -m earth_station.describe` takes several photos and prints how long each one took. Problems (wrong key, no internet, refusal, bad answer) show as a clear message and never crash the station.
- **Camera name** (milestone 4, camera firmware 2.1): the camera announces `cam.local` and answers `GET /id` with `{"board": "camera", "firmware": "2.1.0"}`, so the Earth Station finds it without an IP address. At boot the Serial monitor shows whether it joined the hotspot, its IP address, its name, its AP address and the firmware version.
- **Board finder** (milestone 2): the Earth Station, `--check` and `earth_station.drive` find the rover and camera by themselves: the address in `.env`, then a simulator on this laptop, then `rover.local` / `cam.local` (its own mDNS lookup), then a scan of the hotspot that asks each address `GET /id`. When a board isn't found, it says where it looked.
- **Easy setup** (milestone 1): the hotspot name and password go once into `.env` (`WIFI_SSID`, `WIFI_PASS`). `python -m earth_station.secrets` writes both boards' `secrets.h` from it and makes a random rover token. `python -m earth_station --check` tests the settings files, rover, camera and Jev, and says how to fix each problem.
- **Rover Jev Auto mode** (firmware 2.1): a Jev Auto button, `POST /jev/cmd` with an `X-Token` check, a 1.5 s watchdog, tilt and 20 cm forward vetoes, and moves timed with `millis()`. `/sensors/data` adds `distance_cm`, `mode` and `last_event`. New `GET /id`, `GET /startjev`, and the `rover.local` name. The control page shows the obstacle distance. **The rover's `secrets.h` needs a new `ROVER_CMD_TOKEN` line.**
- Simulator answers `GET /id`.
- Live Jev now follows TypeSafe's official API: options sent as a `criteria` map, `model` field, clear errors for a bad key or rate limit. `JEV_API_URL` defaults to the TypeSafe endpoint, so only `JEV_API_KEY` is needed. Tests check it against the documented examples.
- **Earth Station** (`earth_station/`): a laptop ground station that lets Jev drive the rover. It includes a mock Jev, a built-in rover and camera simulator, a suggest-only mode, a laptop-side safety gate and JSONL run logs.
- One-command setup scripts (`scripts/setup.ps1`, `scripts/setup.sh`), `pyproject.toml`, and 26 tests.
- `docs/EARTH_STATION.md` with the rover protocol for Jev Auto (`distance_cm`, `mode`, `POST /jev/cmd`).
- Design pages in `docs/design/`.
- A CI job that runs the setup, lint and tests on Windows, macOS and Linux.
- `CLAUDE.md`, `CONTRIBUTING.md`, `SECURITY.md` and `docs/ARCHITECTURE.md`.
- `docs/supabase/schema.sql` with the recommended tables and RLS policies.
- GitHub CI: compiles both sketches and runs a gitleaks secret scan.
- Issue templates, a PR template, CODEOWNERS and Dependabot for GitHub Actions.

### Changed
- Without paid vision (`DESCRIBE_MODE=mock`), a real camera photo now tells Jev "No camera vision (photo descriptions are off). Judge what is ahead from the distance sensor only." It used to say the scene was unknown but also mark both sides as clear.
- `.env`: one shared `WIFI_SSID`/`WIFI_PASS` replaces `ROVER_WIFI_*` and `CAM_WIFI_*`.
- `ROVER_URL` and `CAMERA_URL` are now optional and empty by default, meaning "find the board".
- README Quick Start reordered: just the laptop, then the real boards, then the real Jev, then Supabase (optional).
- Credentials moved from the `.ino` files into git-ignored `secrets.h` (template: `secrets.example.h`).
- README rewritten for the current hardware-only setup.

### Removed
- n8n AI workflow (`workflows/`) and the web dashboard (`dashboard/`).

### Fixed
- **The mission control page no longer shows a blank or `-1 cm` distance when the ultrasonic has no echo.** `distance_cm: -1` means "nothing within ~2 m", not a dead sensor; the history table, the live decision step and the sensor box now all say "no reading".
- **The vision rate-limit backoff now really waits 15 → 30 → 60 → 120 s.** The sleep divided the seconds value by 1000 again, so it waited 15–120 **milliseconds** and kept hammering the quota.

## [2.0] - 2026-08-20

- Camera falls back to CIF and a DRAM buffer when PSRAM is missing.

- Camera uploads to Supabase Storage.
