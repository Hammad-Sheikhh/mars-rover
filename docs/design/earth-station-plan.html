Mars Rover · the chosen plan

Earth Station Autopilot

Your laptop becomes mission control. Twice a second it reads the rover's sensors, looks at what the camera sees, asks Jev "what should the rover do next?", and sends the answer back to the rover. The rover's own safety reflexes can always say no, and your phone can always take over.

On the earlier options page this was option 3, the ground station. The "hybrid" you mentioned is the upgrade at the end of this page: a smarter AI that sets goals once the basic loop works.

The big idea

Five parts, one team

Think of it like a person: the rover is the body, the camera is the eyes, and the laptop is the brain that connects them. The laptop asks two online AI services for help: one to describe what the eyes see, and one (Jev) to decide the next move.

BodyRover (ESP32)Has the motors and sensors: distance, tilt, temperature, pressure. Does what it's told, but refuses anything dangerous.
EyesCamera (ESP32-CAM)Takes photos. Already serves them on its own web page, so the laptop can grab one any time.
BrainEarth Station (laptop)A Python program you run. It collects everything, talks to the AIs and sends commands. All secret keys stay here.
DescriberVision AIAn online AI that turns a photo into one sentence: "chair leg ahead, open floor on the right." Your teammate builds this part.
DeciderJevA very fast AI. Given the situation in words, it picks one move from a list (forward, left, right, back, stop) and says how sure it is.

The loop, step by step

Click a step to see where it happens, or press Play. The whole loop takes about half a second and then starts again.

Why describe the photo instead of sending it to Jev?

Jev only understands text. It can't look at pictures. So a vision AI first turns the photo into a short sentence, and Jev reads that sentence. The photo step is slower (1–3 s), so it runs side by side with the driving loop: Jev always uses the most recent description it has.

Five workers running at the same time

A program can do several jobs at once, like a small team. The Earth Station has five "workers". Each does one job at its own speed, so a slow job (describing a photo takes 1–3 s) never holds up a fast one (reading sensors takes about 0.05 s).

EVERY 0.2 sSensor reader

Asks the rover for its latest numbers and writes them on the whiteboard.

in: rover /sensors/dataout: whiteboard.telemetry
EVERY 1–2 sCamera watcher

Grabs a photo, hands it to the teammate's describe function, and writes the description on the whiteboard.

in: camera /captureout: whiteboard.scene
EVERY 0.5 sDecision maker

Reads the whiteboard, writes the situation in words, asks Jev, and passes Jev's answer on.

in: whiteboardout: proposed move
EACH DECISIONSafety gate + sender

Checks the proposed move against the rules below, then sends it to the rover, or sends "stop".

in: proposed moveout: rover /jev/cmd
ALWAYSLogger

Prints each step on screen and saves it to a file, so you can replay a run later and see why the rover turned.

in: everythingout: screen + runs/*.jsonl

Safety gate rules

These run on the laptop before anything reaches the rover. The rover has its own checks too (distance, tilt, watchdog), so there are two layers of protection.

  1. Only drive in Jev mode. If the rover says its mode isn't jev (you pressed a phone button), send nothing.
  2. No old data. Sensor numbers older than 0.5 s or a scene older than 3 s means "stop".
  3. Jev must be sure. If the top choice is under 60%, send "stop" instead.
  4. Don't drive into what Jev itself flagged. If Jev says the path is blocked (over 70%) but its top choice is "forward", send "stop".
  5. Gentle limits. Speed is capped (start at 170 of 255) and every move lasts at most 300 ms.
  6. Errors mean stop. If Jev, the camera or the rover doesn't answer in time, the next command is "stop".

Start-up and shut-down

WHEN YOU START ITPre-flight checks

  1. Load keys and addresses from .env. If something is missing, say which one and quit.
  2. Ping the rover's /sensors/data. If there's no answer, print its address so you can check WiFi.
  3. Grab one test photo from the camera.
  4. Send one tiny test question to Jev to check the key works.
  5. Open a new log file in runs/.
  6. Wait. Nothing moves until you press Jev Auto on the phone.

WHEN YOU STOP ITClean landing

  1. You press Ctrl+C.
  2. It sends "stop" to the rover right away.
  3. It closes the log file and prints a summary: number of decisions, average Jev time, how many moves the rover refused.
  4. Even if the laptop crashes without doing this, the rover's watchdog stops it within 1.5 s.

Suggest-only mode: start it with --suggest and it does everything except step F. It prints what it would send while you drive by phone. That's the safe way to see how Jev behaves before letting it drive.

The main loop in code

This is simplified, but it's close to the real thing. Even if you're new to Python you can follow it: read the whiteboard, describe the situation, ask Jev, check, send, log, wait, repeat.

async def decision_loop(board, rover, jev, gate, log):
    while True:
        if board.mode == "jev":                          # only when you pressed Jev Auto
            text   = state_text.build(board)                # numbers → words
            answer = await jev.ask(text)                    # "turn_right 0.87"
            move   = gate.check(answer, board)              # may turn it into "stop"
            reply  = None
            if not settings.suggest_only:
                reply = await rover.send(move)               # POST /jev/cmd
            log.decision(text, answer, move, reply)
        await asyncio.sleep(settings.decide_every)          # 0.5 s

How the WiFi fits together

Each board does two WiFi jobs at the same time, and it already works this way today:

  • It joins your router (called station mode). That's how the laptop reaches it and how it reaches the internet.
  • It creates its own small WiFi (called AP mode). That's how your phone connects directly to its control page.

One thing to fix first

Right now the rover and the camera join different routers. For this plan, the rover, the camera and the laptop must all be on the same router. That only means changing WIFI_SSID and WIFI_PASS in one secrets.h.

What if something goes wrong

Built to fail safely

AI can be wrong and WiFi can drop. The rule is simple: when in doubt, the rover stops.

What happensWhat the rover does
Jev says "forward" but a wall is 15 cm awayRefuses. Its own distance sensor overrules Jev.
Rover tilts more than 35°Stops the motors.
WiFi drops, or the laptop crashesGets no command for 1.5 s, so it stops by itself (a "watchdog" timer).
Jev isn't sure (under 60%)The laptop sends "stop" instead of guessing.
Someone else on the WiFi tries to send commandsRejected. Commands need a secret token only the laptop knows.
You press a button on the phoneLeaves Jev Auto immediately and does what you pressed.

Later: the hybrid upgrade

Add a planner that sets goals

Jev is quick but short-sighted: it picks the next move and nothing more. Once the loop drives well, add a second, slower AI (such as Claude) to the same laptop program. Every 15 seconds or so it looks at the recent descriptions and sensor history and sets a goal, such as "explore the open area on the right, stay away from the chair". That goal goes into the words Jev reads, so Jev's quick moves start heading somewhere. The same planner can also write a mission report, which is what the old n8n workflow used to do.

Words used on this page

Glossary

AP mode
The board makes its own WiFi network that your phone can join directly. No router needed.
Station mode
The board joins an existing WiFi (your router), like a phone does.
Endpoint
A web address on a board that does one job, such as /sensors/data (gives numbers) or /capture (gives a photo).
API
A way for one program to ask another for something over the internet. Jev and the vision AI are used through their APIs.
API key
A password that proves you're allowed to use an API. Keep it secret; it stays in .env on the laptop.
Telemetry
The stream of sensor numbers the rover reports: distance, tilt, temperature and so on.
Latency
How long you wait for an answer. Jev takes about 0.1–0.5 s.
Watchdog
A timer on the rover. If no command arrives in time, it assumes something broke and stops the motors.
Confidence
How sure Jev is about its answer, from 0% to 100%.
Token
A shared secret the laptop sends with each command, so the rover knows the command is genuine.
Jev details come from third-party write-ups (width.ai, MindStudio). Confirm the request format and pricing in Typesafe AI's own docs when you sign up. Timings on this page are estimates.
